# 模組類型：商品與名貴商品

> 共用的部分（資料讀取、編輯頁框架、sidebar、選擇器、圖片導入、條件清單、輸出規則）見 [主程式規格](../mod_builder.md)。
> 遊戲檔案格式對照 1.15.1。

可以新增商品（工廠生產、消耗的貨物）與名貴商品，也可以修改、覆蓋現有的。狀態：規格撰寫中，請先回覆第 7 節的待確認事項，還沒有開始實作。

## 1. 遊戲中的結構

一種商品牽涉這幾個地方：

| 部分 | 位置 | 內容 | 新商品要不要寫 |
| --- | --- | --- | --- |
| 商品 | `common/goods/` | 圖示、基礎價格、類別、交易、成癮、消費稅、威望 | 要 |
| 投入／產出修正 | `common/modifier_type_definitions/` | `goods_output_<商品>_add`、`goods_input_<商品>_add`：生產方式用這兩個寫產出和投入。原版另外有 23 個產出、6 個投入的 `_mult`（乘數），只給部分商品 | 要（`_add`），不寫生產方式就沒辦法生產 |
| 修正的翻譯 | `localization/` | `goods_output_<商品>_add`「@<商品>!<名稱>產出」與 `_desc`；投入同理 | 要，不然遊戲裡顯示代碼 |
| 文字圖示 | `gui/*.gui` 的 `texticon` | 讓翻譯裡的 `@<商品>!` 顯示成商品圖示（原版在 `gui/goods_texticons.gui`） | 要 |
| 顏色 | `common/named_colors/` | 市場圖表上的顏色（原版 `00_goods_colors.txt`，例如 `coal = hsv360 { 155 5 30 }`） | 要 |
| 人口需求 | `common/pop_needs/` | 人口買哪些商品：每種需求（例如 `popneed_basic_food`）列出可以滿足它的商品與權重 | 人口要買才寫；只給建築用的商品（例如煤、鋼）不用 |
| 翻譯 | `localization/` | 商品名稱 `<商品>`（原版商品沒有 `_desc` 說明） | 要 |
| 圖示 | `gfx/interface/icons/goods_icons/` | 原版都是 256×256 | 要 |
| AI | `common/ai_strategies/` | AI 對各商品的態度（想要出口、想要高供給等） | 不寫也能運作 |

商品的欄位（原版 `common/goods/goods.md`）：

| 欄位 | 內容 | 原版 54 種商品裡有寫的數量 |
| --- | --- | --- |
| `texture` | 圖示 | 54 |
| `cost` | 基礎價格 | 54 |
| `category` | 類別：`staple` 主食（12）、`industrial` 工業（18）、`luxury` 奢侈（17）、`military` 軍事（7）；決定市場畫面的分組 | 54 |
| `prestige_factor` | 生產排行榜最低得獎名次的威望，往上每一名乘 2 | 51 |
| `traded_quantity` | 每一筆世界市場交易的數量，也決定商品轉移條約的船隊成本；預設 10 | 50 |
| `convoy_cost_multiplier` | 當軍需運送時的船隊成本倍數；預設 1 | 32 |
| `obsession_chance` | 人口對它成癮的相對機率；不寫或 0 就不會成癮 | 22 |
| `consumption_tax_cost` | 對它課消費稅的權威成本；不寫就不能課消費稅 | 15 |
| `local` | 只能在生產的地域使用（服務、交通、電力） | 3 |
| `tradeable` | 能不能在世界市場交易；預設可以（金子不行） | 1 |
| `fixed_price` | 價格固定，不隨供需變動（金子） | 1 |
| `pop_consumption_can_add_infrastructure` | 人口消費它會增加基礎設施（汽車） | 1 |

範例（原版 `automobiles`）：

```
automobiles = {
    texture = "gfx/interface/icons/goods_icons/automobiles.dds"
    cost = 100
    category = luxury

    obsession_chance = 1.0
    prestige_factor = 10

    traded_quantity = 3 # 300
    ...
}
```

### 1.1 名貴商品

名貴商品是某種商品的高級版，由公司生產，賣得比較好也帶來威望。

| 部分 | 位置 | 內容 |
| --- | --- | --- |
| 名貴商品 | `common/prestige_goods/` | `base_good` 是哪種商品的高級版、`prestige_bonus` 威望加成、`texture` 圖示、`possible` 條件 |
| 生產的公司 | `common/company_types/` | 公司的 `possible_prestige_goods` 列出它能生產的名貴商品（公司頁已經有這個欄位） |
| 翻譯 | `localization/` | 名稱 `prestige_good_<名稱>`（原版沒有說明） |
| 圖示 | `gfx/interface/icons/goods_icons/prestige_goods/` | 原版都是 256×256 |

原版 76 種名貴商品，`prestige_bonus` 都是 0.1，`possible` 都只有 `has_dlc_feature = mp1_content`（需要「Charters of Commerce」DLC）。同一種商品最多有 3 種名貴商品（例如葡萄酒、菸草、輕武器）。另外有 15 種 `prestige_good_generic_*`，給沒有專屬名貴商品的公司透過事件取得。

```
prestige_good_krupp_guns = {
    possible = {
        has_dlc_feature = mp1_content
    }
    base_good = artillery
    prestige_bonus = 0.1
    texture = "gfx/interface/icons/goods_icons/prestige_goods/krupp_guns_prestige.dds"
}
```

### 1.2 新商品和其他內容的關係

新商品只定義出來不會出現在市場上，要有人生產、有人買：

- **生產**：在工廠頁的生產方式產出這個商品（`goods_output_<商品>_add`）。工具會讓模組裡的新商品出現在生產方式的投入、產出選擇器裡。
- **購買**：建築的生產方式把它當投入，或是放進人口需求（見 3.4）。
- **名貴商品**：新商品也可以有名貴商品；名貴商品要放進某個公司的 `possible_prestige_goods` 才會被生產。

其他模組（例如 3472248460）新增商品時寫的也是第 1 節表上「要」的那幾個檔案。

## 2. 資料

- 讀：`common/goods/`、`common/prestige_goods/`（目前已經讀了圖示、價格、類別、基礎商品，要補齊其他欄位）、`common/pop_needs/`（新讀）、`common/named_colors/` 的商品顏色（新讀）。
- 和公司、工廠、法律一樣，重複定義的商品、名貴商品記錄所有來源與各來源的版本；有其他模組用 `TRY_INJECT` 改過的，合併後顯示。
- 預覽欄要用的「誰生產、誰消耗」：從所有生產方式的投入、產出整理出來（工廠頁的篩選已經有這份資料）。
- 專案檔（`vic_mod_builder.json`）新增 `goods`、`prestige_goods` 兩個清單，記法和法律相同（`mode`：新增或覆蓋，名稱各語言分開記，沒填的語言留空）。

## 3. 畫面

一個「商品」頁同時管「商品」和「名貴商品」兩個 sidebar 分類（和法律頁管法律組、法律相同）。

### 3.0 看板

開始畫面是佔滿中間和右邊的看板，照遊戲市場畫面分成四欄：主食、工業、奢侈、軍事。

- 每種商品一張卡片：圖示、名稱、基礎價格；有來源標籤（和法律相同）。
- 點卡片在下方展開：「修改這個商品」，以及它的名貴商品清單，最下面「＋ 新增名貴商品」（新名貴商品的基礎商品就是這個商品，鎖定，和新增法律時鎖定法律組相同）。
- 每欄最下面「＋ 新增商品」，類別就是這一欄（之後可以在編輯區改）。
- 上方搜尋框，同時找商品和名貴商品。
- 原版標示「已停用」（`# Deprecated`）的風帆戰艦、鐵甲艦照樣列出，不特別處理。

### 3.1 預覽欄

- 商品：圖示、名稱、類別、基礎價格、交易與成癮等設定的摘要；**誰生產**（哪些建築的哪些生產方式產出它）、**誰消耗**（建築投入、人口需求），模組裡的工廠也算進去。
- 名貴商品：圖示、名稱、基礎商品、威望加成、能生產它的公司（遊戲裡的和模組裡的）。

### 3.2 編輯區：商品

| 分頁 | 項目 |
| --- | --- |
| 基本 | 代碼、各語言名稱、圖示（可導入，256×256）、類別、基礎價格 |
| 市場 | 能否交易、只限本地、固定價格、每筆交易數量、船隊成本倍數 |
| 人口 | 成癮機率、消費稅成本、消費增加基礎設施、人口需求（見 3.4） |
| 威望 | 生產排行榜威望 |
| 外觀 | 市場圖表顏色（見第 7 節第 6 題）；文字圖示自動產生，不用設定 |
| 進階 | 工具沒有表單的欄位，以腳本文字框保留 |

### 3.3 編輯區：名貴商品

| 分頁 | 項目 |
| --- | --- |
| 基本 | 代碼（預設 `prestige_good_` 開頭）、各語言名稱、圖示（可導入，256×256）、基礎商品（新增時鎖定）、威望加成（預設 0.1） |
| 條件 | `possible`，用條件清單；新的預設 `has_dlc_feature = mp1_content`，和原版一樣 |
| 公司 | 能生產它的公司（見第 7 節第 5 題） |
| 進階 | 工具沒有表單的欄位 |

### 3.4 人口需求

人口需求在遊戲裡是「一種需求，多種商品可以滿足它」，例如基本食物可以用穀物、魚、肉、雜貨。

- 在商品的「人口」分頁列出這個商品屬於哪些需求，每一項有權重、最大供給佔比、最小供給佔比（原版欄位 `weight`、`max_supply_share`、`min_supply_share`）。
- 可以把它加進現有的需求（下拉選 15 種原版需求，加上其他模組新增的）。
- 預覽欄顯示同一個需求裡其他商品的權重，方便比較。

## 4. 輸出

| 內容 | 檔案 |
| --- | --- |
| 商品 | `common/goods/zzz_<模組>_goods.txt`（覆蓋現有的用 `REPLACE_OR_CREATE:`） |
| 名貴商品 | `common/prestige_goods/zzz_<模組>_prestige_goods.txt`（同上） |
| 新商品的投入／產出修正 | `common/modifier_type_definitions/zzz_<模組>_goods_modifier_types.txt`：每個新商品寫 `goods_output_<商品>_add`（`color = good`）、`goods_input_<商品>_add`（`color = bad`），和原版相同 |
| 文字圖示 | `gui/zzz_<模組>_goods_texticons.gui` |
| 顏色 | `common/named_colors/zzz_<模組>_goods_colors.txt` |
| 人口需求 | `common/pop_needs/zzz_<模組>_pop_needs.txt`：用 `INJECT:popneed_x = { entry = { ... } }` 加進現有需求（3472248460 也是這樣寫） |
| 翻譯 | 商品、名貴商品名稱；新商品的修正名稱與說明，各語言用該語言的商品名稱組成（例如「@x!合金產出」），沒填名稱的語言留空 |
| 圖示 | 導入的圖片照主程式的圖片規則打包 |

修改現有商品時，只有改到的內容才寫：例如只加人口需求，就不覆蓋商品本身。

## 5. 限制與待驗證

- 產生的模組還沒有在遊戲裡實際載入測試。
- 新的 `.gui` 檔裡的 `texticon` 會不會被讀到，要在遊戲裡確認（3472248460 用新檔名 `01_goods_texticons.gui` 加文字圖示，應該可以）。
- 覆蓋現有商品用 `REPLACE_OR_CREATE:` 會整個取代：其他模組用 `TRY_INJECT` 加在同一個商品上的設定，要看載入順序；工具以合併後的版本為基礎，盡量保留。
- 名貴商品實際什麼時候開始生產（公司要達到什麼條件），由遊戲的公司規則決定，工具不處理；要在遊戲裡確認新名貴商品放進公司後會不會出現。
- 刪除模組裡的商品時，如果模組裡的工廠還在用它，要先提醒。

## 6. 初版不做

- 新增人口需求類型（要同時改各財富等級的購買組合 `common/buy_packages/`，影響整個經濟）。
- AI 對商品的態度（`common/ai_strategies/`）。
- 刪除原版商品或名貴商品。
- 新商品的 `_mult` 乘數修正（見第 7 節第 4 題）。
