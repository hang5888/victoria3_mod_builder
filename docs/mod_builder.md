## 1. 專案概述

一個協助製作 Victoria 3 模組的工具。使用者不需要手寫腳本檔，透過圖形介面選擇選項，就能產生可用的模組檔案。

- 前端：以 HTML 呈現。
- 後端：用 Python，負責讀取與寫入檔案。
- 開啟方式：執行 Python 後在本機開一個服務，自動用瀏覽器開啟頁面。
- 語言：支援遊戲內建的全部語言（見第 3 節）。

## 2. 主畫面（導覽頁）

主畫面是一個導覽頁面，有三個用途。

### 2.1 顯示可製作的模組類型

列出這個工具能做的模組類型（見文件開頭的表），點選後進入對應的 builder。

〔初版做法〕首頁的配置：

- 最上方是標題區：說明文字、目前狀態（遊戲版本、正在編輯的模組、已加載的資料量），以及五個步驟的進度（文件夾 → 要讀取的模組 → 加載遊戲資料 → 你的模組 → 開始製作）。完成的步驟打勾，下一個要做的步驟標出來；點步驟會捲到對應的區塊。
- 模組類型用大卡片顯示，資料加載後卡片上有遊戲的圖片，並標出這個模組裡已有幾項。前面的步驟都完成時，類型卡片排在設定區塊上面；還沒完成時排在最下面並停用，卡片上說明還缺哪一步。
- 設定區塊分兩欄：左邊是文件夾、加載遊戲資料、你的模組，右邊是要讀取的模組清單。畫面窄時改為一欄。

### 2.2 選擇資料夾

使用者需要指定三個資料夾：

| 資料夾 | 用途 | 常見位置 |
| --- | --- | --- |
| 遊戲本體 | 讀取原版資料 | `<Steam>/steamapps/common/Victoria 3/game/` |
| Steam 工作坊 | 讀取已訂閱的模組 | `<Steam>/steamapps/workshop/content/529340/` |
| 本地模組 | 讀取本地模組，也是輸出位置 | `文件/Paradox Interactive/Victoria 3/mod/` |

〔初版做法〕

- 選過的路徑會記住（存在工具資料夾的 `settings.json`），下次開啟不用重選。
- 可以自動偵測常見位置，偵測不到再請使用者手動選。
- 選完後檢查資料夾是否正確（例如遊戲本體底下要有 `common/`），不正確就提示。

### 2.3 選擇要加載的模組

資料夾選好後，列出工作坊和本地的所有模組，由使用者決定要加載哪些。只有被選中的模組會被讀取。

- **手動勾選**：勾選要加載的模組，並可調整先後順序。
- **匯入播放清單**：讀取遊戲啟動器裡設定好的播放清單（模組與順序）當起點，匯入後仍可再手動調整。播放清單存在本地模組資料夾旁的 `launcher-v2.sqlite`。

〔初版做法〕

- 順序決定衝突時誰優先：排在後面的模組覆蓋排在前面的，和遊戲的規則一致。
- 勾選結果會記住，下次開啟時沿用。

## 3. 語言

### 3.1 支援的語言

以遊戲內建的語言為準，不另外支援繁體中文。

遊戲內建 11 種語言：英文、巴西葡萄牙文、法文、德文、日文、韓文、波蘭文、俄文、簡體中文、西班牙文、土耳其文。實際清單在讀取時從遊戲本體的翻譯資料夾取得，不寫死在程式裡。

### 3.2 角落的語言選擇

畫面角落有一個語言選擇，切換後以下三者一起改變：

| 項目 | 切換後的行為 |
| --- | --- |
| 工具介面文字 | 按鈕、標題、提示改用該語言（目前範圍見下方） |
| 遊戲與模組資料 | 公司名、州名、產業名等改用該語言的翻譯顯示 |
| 名稱欄位 | 編輯區只顯示該語言的欄位，編輯的是該語言的翻譯 |

工具介面文字先只做**英文和簡體中文**。切到其他語言時，介面文字顯示英文，遊戲與模組資料仍用該語言顯示。其他語言的介面翻譯之後再補。

### 3.3 為模組新增不同語言

正在製作的模組可以有多種語言的翻譯。要填另一個語言，就用角落的語言選擇切換過去再填。

使用者沒有填的語言，輸出時留空，不用其他語言補上。遊戲切到那個語言時會顯示內部代碼。

〔初版做法〕

- 預覽欄標示哪些語言已填、哪些還沒填。
- 某筆資料在目前語言沒有翻譯，或翻譯只有腳本（例如模組把政黨名稱換成 `[...GetCustom(...)]`）時，改顯示英文；英文也沒有就顯示內部代碼。

## 4. 資料讀取

資料夾和模組選取完成後，先讀取共用的資料，供各個 builder 使用。各類型自己的資料（例如現有公司）寫在該類型的文件。

| 資料 | 用途 | 來源位置 |
| --- | --- | --- |
| 各種 buff / debuff | 加成的選項 | `common/modifier_type_definitions/` |
| 產業（建築） | 建築選項（圖示來自各建築的 `icon`） | `common/buildings/`、`common/building_groups/` |
| 名貴商品 | 名貴商品選項（圖示來自各商品的 `texture`） | `common/prestige_goods/` |
| 科技 | 條件的科技選項（圖示 `texture`，時代 `era`） | `common/technology/technologies/` |
| 國家 | 條件的國家選項 | `common/country_definitions/` |
| 文化 | 條件的文化選項 | `common/cultures/` |
| 翻譯文件 | 把內部代碼顯示成可讀的名稱 | `localization/<語言>/`（`*_l_<語言>.yml`，UTF-8 BOM） |
| 州名稱 | 州的選項、地圖標示 | `map_data/state_regions/` |
| 戰略區域 | 依地區篩選、地圖分區 | `common/strategic_regions/` |
| 省份 | 組成地圖 | `map_data/provinces.png` |

### 4.1 遊戲版本

以使用者選擇的遊戲本體的版本為準。來源位置與檔案格式會隨版本變動，實作前要對照實際的遊戲檔案。

讀取時從遊戲資料夾的 `launcher/launcher-settings.json` 取得版本號，顯示在畫面上，建立模組時也寫進模組資訊檔（`.metadata/metadata.json`）。

### 4.2 地圖

省份和州都要讀取：

1. 從省份圖檔讀出每個省份的形狀。
2. 從州的定義檔讀出每個州包含哪些省份。
3. 把省份合併成州，再配上翻譯後的州名稱，組成一張地圖。

地圖除了用來選州，也顯示其他資訊，例如現有公司的總部分布。

### 4.3 來源的合併

- 讀取遊戲本體，加上第 2.3 節選中的模組。
- 同一個代碼在遊戲本體與模組都有定義時，**模組優先**。
- 〔初版做法〕多個模組定義同一個代碼時，依第 2.3 節的順序決定。
- 〔初版做法〕每筆資料記錄來源（遊戲本體／模組名稱），供篩選使用。需要時也可以記錄每個來源載入後的版本（目前公司有用，見公司文件）。
- 〔初版做法〕讀取時畫面上顯示進度條與目前的步驟。

## 5. 編輯頁（各模組類型共用）

### 5.1 畫面配置

四欄式：

| Sidebar | 預覽欄 | 編輯區 | 現有項目 |
| --- | --- | --- | --- |
| 這個模組的所有修改 | 正在編輯的項目摘要 | 各種選項 | 遊戲與已加載模組中的現有項目（可篩選） |

畫面寬度不足（1240px 以下）時改為上下排列。各類型在這個框架裡放自己的內容。

〔初版做法〕

- 初始畫面：剛進入編輯頁時不開啟任何項目，編輯區只有一個「新公司」／「新工廠」按鈕；也可以從 sidebar 開啟已保存的項目，或從右欄選現有項目來修改、複製。
- 編輯中：預覽欄標題旁是「保存」按鈕，預覽欄最下面是「新公司」／「新工廠」按鈕（有未保存的修改時先確認）。編輯區右上角的 ✕ 關閉目前的項目並回到初始畫面（有未保存的修改時先確認）。
- 刪除正在編輯的項目後回到初始畫面。

### 5.2 Sidebar：模組內容

所有編輯頁共用（首頁不顯示）。

〔初版做法〕

- 標題旁的 « 按鈕可以收起整個 sidebar，收起後只剩一條窄欄（» 與直書的「模組內容」，有未保存的修改時加一個小圓點），點窄欄任何地方就展開；收起狀態會記住。
- 列出這個模組的所有修改，依類型分類（公司、工廠、奇觀、法律組、法律、國家開局），每個分類可以收合／展開，收合狀態會記住（存在瀏覽器）。
- 只列出已經保存到模組的內容：新的項目、或對現有項目的修改，都要按「保存到模組」之後才會出現或更新。
- 每一項顯示名稱、代碼、新增／覆蓋標記；正在編輯的項目會標出來，有未保存的修改時加上「未保存」標記（名稱與代碼仍是已保存的內容）。
- 點一項就載入編輯（有未保存的修改時先確認）；✕ 刪除（先確認）。
- 其他類型的項目也會列出：點了會切到那個類型的編輯頁並開啟它；刪除要到該類型的編輯頁操作。切換頁面時，原本頁面未保存的修改會保留。
- 還沒保存過的新項目不會出現在清單裡；要放棄它，按編輯區右上角的 ✕（會先確認）。
- 底部固定兩個按鈕：
  - 「保存到模組」：只保存 sidebar 列出的模組內容，依專案檔重新產生整個模組的檔案；不會保存編輯區裡正在編輯的項目（那要用預覽欄標題旁的「保存」）。
  - 「打開模組文件夾」：用系統的檔案總管開啟目前模組的資料夾（後端只會開啟目前模組的資料夾）。

### 5.3 共用元件

#### 5.3.1 選擇器

選建築、商品、州、科技等都用同一個可搜尋的選擇器，可單選或多選；建築、名貴商品、科技、法律顯示圖示。少數建築（多為奇觀）在遊戲檔案裡沒有圖示，顯示空白。

#### 5.3.1.1 圖片欄位與導入

所有圖片欄位（公司的圖示與背景、建築的圖示與背景、生產方式組與生產方式的圖示、法律圖示）都可以「選擇…」遊戲和已加載模組的圖片，或「導入…」自己的圖片。

| 種類 | 尺寸 | 不同比例時 |
| --- | --- | --- |
| 公司圖示 | 256×256 | 等比縮放放進正方形，空白處透明 |
| 公司背景 | 1027×496 | 等比縮放填滿，以中央為準裁切 |
| 建築圖示 | 256×256 | 同公司圖示 |
| 建築背景 | 652×256 | 同公司背景 |
| 生產方式組圖示 | 120×120 | 同公司圖示 |
| 生產方式圖示 | 104×104 | 同公司圖示 |
| 法律圖示 | 302×302 | 同公司圖示 |

- 瀏覽器讀得到的格式（PNG、JPG、WebP 等）在瀏覽器裡縮放成上表的尺寸，存成 PNG；導入前顯示預覽。`.dds` 檔原樣導入，不縮放。尺寸取自原版 1.15.1 的圖片。
- 最大 20 MB。檔名取原檔名，加上種類與內容雜湊（例如 `company_icon_my_logo_89a3742b.png`），同一張圖只會存一份。
- 導入後先放在模組資料夾的 `.vmb_images/`，並記在專案檔；欄位寫的是之後的遊戲路徑 `gfx/interface/icons/<模組>_images/<檔名>`，工具在打包前也能顯示它。
- 導入的圖片在選擇器裡排最前面，標示「已導入」，同種類的欄位都選得到。
- 保存時（任何一種保存）：有已保存項目使用的圖片複製到 `gfx/interface/icons/<模組>_images/`；沒有使用的從模組刪除。編輯頁正在編輯、還沒保存的項目所用的圖片會保留，不打包也不刪。

#### 5.3.2 條件清單

腳本裡的條件區塊（例如顯示條件、可達成條件）用清單編輯：每列一個條件，用選擇器選值，不用打字；所有列都要滿足。每個區塊可用的條件類型由該模組類型決定。

| 條件類型 | 寫出的腳本 |
| --- | --- |
| 已研究科技 | `has_technology_researched = X` |
| 擁有建築（可多選、等級、地域可留空、已整合） | 一個建築且有地域：`has_building_levels_in_state_region`；其他：`any_scope_state` + `any_scope_building` |
| 擁有地域中的地區（已整合） | `any_scope_state = { state_region = s:X }` |
| 擁有整個地域 | `owns_entire_state_region = X` |
| 在戰略區域有利益（可多選） | `has_interest_marker_in_region = sr:X`，多個時用 `OR` |
| 國家是（可多選） | `c:TAG ?= this`，多個時用 `OR` |
| 主要文化包括（可多選） | `country_has_primary_culture = cu:X`，多個時用 `OR` |
| 需要 DLC 功能 | `has_dlc_feature = X` |
| 地域是、地區已整合（用於以州為範圍的區塊） | `state_region = s:X`、`is_incorporated = yes` |
| 建造目標（建築＋等級＋地域） | `building_x = { level = N state_trigger = { ... } }` |
| 腳本 | 原樣寫入 |

- 腳本文字仍是儲存的內容；畫面把腳本讀成清單，改動清單時重新寫出腳本。
- 認不出的條件顯示成「腳本」列，保留原文，位置不變。
- 每個區塊都可以展開「腳本（進階）」直接編輯；括號不成對時清單暫停，修正後恢復。
- 可以選擇是否提供「在遊戲中隱藏」選項（寫成 `hidden_trigger`）。

〔初版做法〕DLC 功能沒有翻譯名稱，清單顯示代碼；清單來源是 1.15.1 遊戲檔案中用到的 21 個，加上已讀取資料用到的。科技時代也沒有翻譯名稱，顯示為「時代 N」。

## 6. 輸出

所有的新增與修改都寫在這個工具建立的模組裡，**不修改遊戲本體和其他模組的檔案**（工作坊模組、不是這個工具建立的本地模組都算）。

- 輸出時可以建立新模組，也可以打開這個工具之前建立的模組繼續編輯。
- 修改現有項目時，在輸出的模組裡寫一份同代碼的定義來覆蓋，原始檔案不動。

〔初版做法〕

- 輸出位置是本地模組資料夾，產生的模組可直接在遊戲啟動器啟用。
- 工具建立的模組裡有 `vic_mod_builder.json`，用來分辨哪些模組可以繼續編輯；這個檔案是編輯內容的原始資料，每次儲存時依它重新產生遊戲檔案。工具只會寫入或刪除自己產生的檔案。
- 模組資訊：`.metadata/metadata.json`（名稱、版本、對應的遊戲版本）。
- 翻譯只輸出有填寫的語言；覆蓋現有項目的名稱寫在 `localization/<語言>/replace/`。
- 覆蓋現有項目的寫法：`REPLACE_OR_CREATE:<代碼> = { ... }`（1.15.1 支援），覆蓋時寫出完整的定義。
- 導入的圖片：使用中的打包到 `gfx/interface/icons/<模組>_images/`（見 5.3.1.1）。
- 各類型輸出的檔案寫在該類型的文件。

## 7. 新增模組類型

新增一個類型時要做的事：

1. 在 `docs/mod_types/` 新增該類型的文件，並加進本文件開頭的表。
2. 後端：讀取該類型的現有資料、輸出檔案、驗證；專案檔加上該類型的清單。
3. 前端：新增編輯頁（路由、導覽），在 `frontend/js/sidebar.js` 的 `KINDS` 加一個分類（分類名稱就是該頁的路由）；表單、圖片選擇、來源標籤等共用元件在 `frontend/js/widgets.js`。
4. 介面文字加進 `frontend/i18n/en.json` 與 `zh-hans.json`（測試會檢查兩邊一致、沒有遺漏或多餘的鍵）。

## 8. 初版實作狀態

執行方式：`python app.py`（只需要 Python 3，不用安裝其他套件），會開啟 `http://127.0.0.1:8765/`。測試：`python -m unittest discover tests`。

初版的限制：

- 還沒有在遊戲裡實際載入產生的模組測試過。
- 導入的 PNG 圖片還沒有在遊戲裡實際測試顯示（工坊已有模組使用 .png 圖示）。
- 這個工具建立的模組不會被當成資料來源讀取（避免讀到自己正在編輯的內容）。
- 工具建立的模組在遊戲裡應該排在其他模組後面，覆蓋才會生效。
- 模組的 `INJECT:` 等部分修改寫法在讀取時是近似處理。
- 條件清單沒有「不是…」（`NOT`）、法律、遊戲規則等條件，這些以腳本列保留。
- 透過清單改動某個條件區塊時，該區塊中條件之間的註解（`#`）會消失（腳本列內部的註解會保留）。
